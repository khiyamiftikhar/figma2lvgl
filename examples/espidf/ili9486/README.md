# ESP-IDF example: ILI9486 (320×480) with XPT2046 touch, ESP32 or ESP32-C3

A complete ESP-IDF project that shows the `home` screen generated by
figma2lvgl from `design/ili9486.xml`: two labels, a progress bar, two
images and a button with click and long-press callbacks.

## Layout

```
ili9486/
  design/
    ili9486.xml        FigML export of the "home" frame
    icon_wifi.png      image assets used by the design
    wifi_off.png
  main/                application code (display, touch, callbacks)
  ui_src/              generated by figma2lvgl (git-ignored)
  dependencies.lock    exact component versions (committed)
  sdkconfig.defaults           shared settings (resolution, touch threshold)
  sdkconfig.defaults.esp32     ESP32 pins
  sdkconfig.defaults.esp32c3   ESP32-C3 pins and console
```

ESP-IDF applies `sdkconfig.defaults` and then the file for the selected
target. The touch chip-select is the example's own setting
(`idf.py menuconfig` → "figma2lvgl example"), since the XPT2046 component
has none; touch shares the display's SPI host and bus pins.

`main/CMakeLists.txt` compiles every file figma2lvgl generated, so a
regenerated `ui_src/` builds without editing it. Set the
`FIGMA2LVGL_UI_SRC` environment variable to build against generated output
in another folder (CI does this).

## Build

From the repository root, in an ESP-IDF terminal:

```
python -m figma2lvgl.main -x examples/espidf/ili9486/design/ili9486.xml -i examples/espidf/ili9486/design -d examples/espidf/ili9486 -y
cd examples/espidf/ili9486
idf.py set-target esp32c3      # or esp32
idf.py build flash monitor
```

`python -m figma2lvgl.main` runs the figma2lvgl in this checkout, not an
installed copy. Image conversion needs `pypng` and `lz4` in that Python
(`pip install pypng lz4`).

The first build resolves components exactly as `dependencies.lock` says.
To update a component, change `main/idf_component.yml`, run
`idf.py update-dependencies`, and commit the new lockfile.

`sdkconfig` and `build/` are per target. To keep several targets side by
side, give each its own build folder and config (both git-ignored), and
list the shared defaults file before the target's own.

**ESP32** (PowerShell)

```
$env:IDF_TARGET="esp32"
idf.py -B build_esp32 -D SDKCONFIG=sdkconfig.esp32 -D SDKCONFIG_DEFAULTS="sdkconfig.defaults;sdkconfig.defaults.esp32" -D IDF_TARGET=esp32 build
```

**ESP32-C3** (PowerShell)

```
$env:IDF_TARGET="esp32c3"
idf.py -B build_esp32c3 -D SDKCONFIG=sdkconfig.esp32c3 -D SDKCONFIG_DEFAULTS="sdkconfig.defaults;sdkconfig.defaults.esp32c3" -D IDF_TARGET=esp32c3 build
```

Add `flash monitor` after `build` to flash and watch the log.

## Wiring

| Signal | ESP32 | ESP32-C3 |
|---|---|---|
| MOSI | 23 | 7 |
| MISO | 19 | 20 |
| CLK | 18 | 6 |
| Display CS | 5 | 10 |
| DC | 21 | 5 |
| RST | 22 | 4 |
| Backlight | driver default | 3 |
| Touch CS | 25 | 1 |

ESP32-C3 notes: GPIO8 drives the onboard LED on most boards, so a touch CS
there makes the LED flicker at the touch polling rate. GPIO2, GPIO8 and
GPIO9 are strapping pins. GPIO20 is UART0 RX, free because the console runs
over USB-Serial-JTAG.
